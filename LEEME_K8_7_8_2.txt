K.8.7.8.2 — Collaboration transaction hotfix

DIAGNÓSTICO
K.8.7.8 endureció el borrado de archivos para ejecutarlo con
transaction.on_commit(), pero colaboracion/services.py no importaba
django.db.transaction.

SÍ corrige:
- eliminar mensaje del Planner;
- limpiar historial del canal;
- borrado físico diferido de adjuntos después del COMMIT.

NO cambia:
- permisos;
- rutas;
- modelos;
- migraciones;
- base de datos;
- Builder;
- templates;
- comportamiento Cliente/Proveedor.

Los warnings 403 en las pruebas de Cliente son esperados: comprueban que un
rol externo no puede utilizar herramientas destructivas del Planner.

APLICACIÓN
Copiar el contenido de K8_7_8_2_HOTFIX sobre el proyecto actual
(K.8.7.8 + K.8.7.8.1).

No ejecutar migrate.

Ejecutar:
  python scripts/verify_hotfix_k8_7_8_2.py

Si termina:
  K.8.7.8.2 transaction hotfix: OK

ejecutar inmediatamente:
  python scripts/verify_stable_k8_7_8.py
